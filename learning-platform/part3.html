Traditional databases store text, numbers, and dates. SELECT
    ui.input_text,
    ui.input_type,
    p.prediction_label,
    1 - (e.embedding <=> $1::vector) AS similarity  -- cosine similarity (not distance)
FROM embeddings e
JOIN user_inputs ui ON ui.id = e.input_id
JOIN predictions p ON p.input_id = ui.id
WHERE e.input_type = 'lead_message'
  AND e.user_id = $2::uuid
ORDER BY e.embedding <=> $1::vector  -- ORDER BY cosine distance (smaller = more similar)
LIMIT 5;

🅆 sentence-transformers + FAISS

Used in your AI Market Research Copilot. sentence-transformers converts text to semantic embeddings; FAISS performs lightning-fast nearest-neighbor search on those embeddings.

sentence-transformers — What It Does

all-MiniLM-L6-v2 is a fine-tuned BERT model that maps any sentence to a 384-dimensional vector such that semantically similar sentences have vectors that are close together in the vector space.

  • “I want to sell my coaching program online” → [0.12, -0.43, 0.87, ...] (384 floats)
  • “monetize my mentoring service on the internet” → [0.11, -0.45, 0.86, ...] (very close!)
  • TF-IDF would give these a score of 0 (no shared keywords). sentence-transformers gives them cosine similarity ≈ 0.92.

Why all-MiniLM-L6-v2 specifically?

  • 384 dims (smaller = faster, still very good quality)
  • Runs on CPU (no GPU needed)
  • ~22MB model size (fast to load)
  • Open source, free, runs locally (no API cost)
  • Good balance of speed and accuracy for general English text

import faiss
import numpy as np
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("all-MiniLM-L6-v2")

class FAISSVectorStore:
    def __init__(self, dim: int = 384):
        # IndexFlatIP: exact inner product search (= cosine similarity when normalized)
        self.index = faiss.IndexFlatIP(dim)
        self.texts = []      # parallel list: texts[i] corresponds to index vector i
        self.metadata = []   # chunk metadata (source file, page, etc.)

    def add_texts(self, texts: list[str], metadata: list[dict]):
        embeddings = model.encode(texts, normalize_embeddings=True)
        # faiss expects float32 C-contiguous array
        embeddings = np.array(embeddings, dtype=np.float32)
        self.index.add(embeddings)   # adds vectors to the index
        self.texts.extend(texts)
        self.metadata.extend(metadata)
        print(f"Index now has {self.index.ntotal} vectors")

    def search(self, query: str, k: int = 5) -> list[dict]:
        query_emb = model.encode([query], normalize_embeddings=True)
        query_emb = np.array(query_emb, dtype=np.float32)

        # D = distances (inner product scores, range 0-1 since normalized)
        # I = indices into self.texts
        D, I = self.index.search(query_emb, k)

        results = []
        for score, idx in zip(D[0], I[0]):
            if idx == -1:  # -1 means no result found
                continue
            results.append({
                "text": self.texts[idx],
                "score": float(score),        # cosine similarity
                "metadata": self.metadata[idx]
            })
        return results   # already sorted by score descending

    def save(self, path: str):
        faiss.write_index(self.index, path + ".faiss")
        # also save texts and metadata with pickle/json

    def load(self, path: str):
        self.index = faiss.read_index(path + ".faiss")
Mental Model

Think of sentence-transformers as translating text into a location in a 384-dimensional space where cities (texts) with similar meaning are geographically close. FAISS is the GPS system that finds your K nearest cities from any starting point, searching millions of locations in milliseconds by organizing them into spatial partitions.

# Document parsing (simplified from your document_parser.py)
import PyPDF2, csv

def parse_document(file_path: str, content_type: str) -> str:
    if content_type == "application/pdf":
        reader = PyPDF2.PdfReader(file_path)
        return "\n".join(page.extract_text() for page in reader.pages)
    elif content_type == "text/csv":
        with open(file_path) as f:
            return "\n".join(",".join(row) for row in csv.reader(f))
    else:  # text/plain, text/markdown
        return open(file_path).read()

# Chunking: split long text into overlapping chunks
# Why overlap? Important context at chunk boundaries is not lost.
# If sentence A is at end of chunk 1 and related sentence B is at start of chunk 2,
# the overlap ensures both appear together in at least one chunk.
def chunk_text(
    text: str,
    chunk_size: int = 500,   # characters per chunk
    overlap: int = 50        # overlap between consecutive chunks
) -> list[str]:
    chunks = []
    start = 0
    while start < len(text):
        end = start + chunk_size
        chunk = text[start:end]
        if chunk.strip():  # skip empty chunks
            chunks.append(chunk)
        start = end - overlap  # move forward by (chunk_size - overlap)
    return chunks

# Example:
text = "...a 3000-character market research document..."

# Result: ~6-7 chunks, each 500 chars, 50 chars shared with neighbors

3-Layer Fallback Strategy (from your system design doc)

When AI providers fail, you need resilience. Your documented strategy has 3 layers:

  • Layer 1 — Retry with exponential backoff: Try same provider 3x with delays of 1s, 2s, 4s. Handles transient errors (rate limits, temporary outages).
  • Layer 2 — Provider fallback: If primary (Stability AI / Claude) exhausts retries, switch to backup provider (DALL-E / GPT-4). Same request, different provider.
  • Layer 3 — Job queue: If all providers fail, push to SQS/BullMQ. Worker retries in 60 seconds. User gets immediate response: “Content queued, we'll notify you.”
3-layer fallback from your system_design_answers (JavaScript pseudocode)
async function generateWithFallback(request) {
  const providers = [primaryProvider, backupProvider];

  for (const provider of providers) {
    for (let attempt = 1; attempt <= 3; attempt++) {
      try {
        // withTimeout ensures we don't wait forever
        return await withTimeout(provider.generate(request), 30_000);
      } catch (err) {
        if (attempt < 3) {
          await sleep(attempt * 1000);  // exponential: 1s, 2s (not 4s since capped at 3)
        }
        console.error(`Provider ${provider.name} attempt ${attempt} failed:`, err);
      }
    }
  }

  // Layer 3: all providers exhausted
  await jobQueue.add('generate', request, { delay: 60_000 });
  return { status: 'queued', message: 'Content queued. You will be notified.' };
}

async/await — complete mental model
import asyncio

# async def creates a coroutine function.
# Calling it returns a coroutine object (not the result).
async def fetch_data(url: str) -> dict:
    # await suspends THIS coroutine, giving up the event loop
    # to run other coroutines while waiting for the HTTP response.
    # The thread is NOT blocked — it runs other tasks.
    response = await httpx.AsyncClient().get(url)
    return response.json()

# Running multiple async tasks CONCURRENTLY (not in parallel threads)
async def main():
    # asyncio.gather runs all 3 coroutines concurrently
    # Total time ≈ max(t1, t2, t3), not t1+t2+t3
    results = await asyncio.gather(
        fetch_data("https://api1.example.com"),
        fetch_data("https://api2.example.com"),
        fetch_data("https://api3.example.com"),
    )

# Common mistake: calling blocking code in async context
async def bad_example():
    time.sleep(5)        # WRONG: blocks the entire event loop!
    data = open("file.txt").read()  # OK for small files, but still blocking

async def good_example():
    await asyncio.sleep(5)      # yields control while sleeping
    async with aiofiles.open("file.txt") as f:  # async file I/O
        data = await f.read()
