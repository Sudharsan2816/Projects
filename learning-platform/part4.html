Claude is Anthropic's family of large language models. The API follows the Messages format — stateless, with explicit system/human/assistant turns. Understanding the model tiers, pricing, and advanced features like prompt caching and tool use is essential for production AI apps.

Messages API Structure

COREEvery API call is a Messages request
import anthropic

client = anthropic.Anthropic(api_key="sk-ant-...")

message = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=1024,
    system="You are a senior Python engineer. Be concise.",
    messages=[
        {"role": "user", "content": "Explain async/await in 3 bullet points"}
    ]
)
print(message.content[0].text)

# Response object structure:
# message.id          → unique message ID
# message.model       → model used
# message.usage       → {input_tokens, output_tokens}
# message.stop_reason → "end_turn" | "max_tokens" | "tool_use"
# message.content     → list of content blocks

Tool Use (Function Calling)

ADVANCEDGive Claude access to external functions

Tool use lets Claude call external functions in a structured loop. You define tools, Claude decides when to call them, you execute and return results.

tools = [
    {
        "name": "get_weather",
        "description": "Get current weather for a city",
        "input_schema": {
            "type": "object",
            "properties": {
                "city": {"type": "string", "description": "City name"},
                "unit": {"type": "string", "enum": ["celsius", "fahrenheit"]}
            },
            "required": ["city"]
        }
    }
]

# First call — Claude decides to use tool
response = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=1024,
    tools=tools,
    messages=[{"role": "user", "content": "What's the weather in London?"}]
)

# response.stop_reason == "tool_use"
tool_use = response.content[1]  # ToolUseBlock
tool_name = tool_use.name       # "get_weather"
tool_input = tool_use.input     # {"city": "London"}

# Execute the tool yourself
result = my_get_weather(tool_input["city"])

# Second call — send back the result
response2 = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=1024,
    tools=tools,
    messages=[
        {"role": "user", "content": "What's the weather in London?"},
        {"role": "assistant", "content": response.content},
        {"role": "user", "content": [
            {
                "type": "tool_result",
                "tool_use_id": tool_use.id,
                "content": f"Weather: {result}"
            }
        ]}
    ]
)
💡 Tip Use tool_choice={"type": "any"} to force Claude to use a tool, or {"type": "tool", "name": "..."} to force a specific tool. Default is {"type": "auto"}.

Prompt Caching

COST SAVINGCache repeated context — up to 90% cost reduction

Prompt caching stores expensive prefill computations server-side for 5 minutes (or 1 hour with extended cache). Reusing a 100K-token system prompt cuts costs from $3/M to $0.30/M tokens.

# Mark content for caching with cache_control
response = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=1024,
    system=[
        {
            "type": "text",
            "text": "You are an expert code reviewer...",
            "cache_control": {"type": "ephemeral"}  # Cache this block
        },
        {
            "type": "text",
            "text": long_codebase_context,  # 50K token codebase
            "cache_control": {"type": "ephemeral"}  # Cache this too
        }
    ],
    messages=[{"role": "user", "content": "Review the auth module"}]
)

# Check cache performance
usage = response.usage
print(f"Cache creation tokens: {usage.cache_creation_input_tokens}")
print(f"Cache read tokens: {usage.cache_read_input_tokens}")  # Cheap!
print(f"Regular input tokens: {usage.input_tokens}")

# Pricing comparison (Sonnet):
# Regular input:  $3.00 / 1M tokens
# Cache write:    $3.75 / 1M tokens (one-time)
# Cache read:     $0.30 / 1M tokens (90% cheaper!)

Streaming

import anthropic

client = anthropic.Anthropic()

# Method 1: stream context manager (recommended)
with client.messages.stream(
    model="claude-sonnet-4-6",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Write a haiku about Python"}]
) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)

    final_message = stream.get_final_message()
    print(f"\nTotal tokens: {final_message.usage.input_tokens + final_message.usage.output_tokens}")

# Method 2: raw events
with client.messages.stream(...) as stream:
    for event in stream:
        if event.type == "content_block_delta":
            print(event.delta.text, end="", flush=True)
        elif event.type == "message_delta":
            print(f"\nStop reason: {event.delta.stop_reason}")

🧠 Quiz: Claude API

1. When Claude responds with stop_reason = "tool_use", what should your code do next?

✅ Correct! Tool use is a loop: Claude requests → you execute → you return result → Claude continues reasoning.
❌ Wrong. tool_use means Claude wants to call a function. You must execute it and return a tool_result in a follow-up message.

2. Prompt caching reduces costs by up to 90%. What does the cache_control header actually cache?

✅ Correct! Anthropic caches the key-value attention states for those content blocks server-side for 5 minutes, so prefill is skipped on cache hits.
❌ Wrong. The cache stores the KV attention states for marked blocks. Cache reads cost 0.30/1M vs 3.00/1M for regular input (Sonnet).

3. Which model should you use for a high-volume classification task that needs to run 10,000 times/hour cheaply?

✅ Correct! Haiku is fastest and cheapest — perfect for high-volume classification, routing, and extraction tasks where you don't need Opus-level reasoning.
❌ Wrong. Haiku is the right choice for high-volume, low-complexity tasks. Opus is overkill and expensive for classification.

3. LangGraph — Advanced Patterns

LangGraph models AI workflows as directed graphs where nodes are functions and edges are transitions. State flows through nodes, enabling complex multi-step reasoning, branching, loops, and human-in-the-loop workflows.

Core Concepts

→
Node (fn)
→
Edge / Condition
→
Next Node
→
END

StateGraph — Full Pattern

from langgraph.graph import StateGraph, END
from langgraph.checkpoint.memory import MemorySaver
from langchain_anthropic import ChatAnthropic
from langchain_core.messages import HumanMessage, AIMessage
from typing import TypedDict, Annotated, List
import operator

# 1. Define state
class AgentState(TypedDict):
    messages: Annotated[List, operator.add]  # Appends messages, doesn't overwrite
    iteration: int
    final_answer: str

# 2. Define nodes (pure functions: state -> state update dict)
llm = ChatAnthropic(model="claude-sonnet-4-6")

def agent_node(state: AgentState) -> dict:
    response = llm.invoke(state["messages"])
    return {"messages": [response], "iteration": state["iteration"] + 1}

def tool_node(state: AgentState) -> dict:
    last_msg = state["messages"][-1]
    # Execute tool calls from last message
    results = execute_tools(last_msg.tool_calls)
    return {"messages": results}

def summarize_node(state: AgentState) -> dict:
    summary = llm.invoke([HumanMessage(content="Summarize: " + str(state["messages"]))])
    return {"final_answer": summary.content}

# 3. Routing function
def should_continue(state: AgentState) -> str:
    last_message = state["messages"][-1]
    if hasattr(last_message, "tool_calls") and last_message.tool_calls:
        return "use_tools"
    elif state["iteration"] >= 5:
        return "summarize"
    else:
        return "end"

# 4. Build graph
workflow = StateGraph(AgentState)
workflow.add_node("agent", agent_node)
workflow.add_node("tools", tool_node)
workflow.add_node("summarize", summarize_node)

workflow.set_entry_point("agent")
workflow.add_conditional_edges("agent", should_continue, {
    "use_tools": "tools",
    "summarize": "summarize",
    "end": END
})
workflow.add_edge("tools", "agent")       # Loop back
workflow.add_edge("summarize", END)

# 5. Compile with checkpointing
memory = MemorySaver()
app = workflow.compile(checkpointer=memory)

# 6. Run
config = {"configurable": {"thread_id": "user-123"}}
result = app.invoke(
    {"messages": [HumanMessage(content="Research the latest AI news")], "iteration": 0},
    config=config
)
print(result["messages"][-1].content)

Human-in-the-Loop with interrupt_before

IMPORTANTPause execution for human approval
from langgraph.types import interrupt, Command

# Method 1: interrupt_before — pause BEFORE a node runs
app = workflow.compile(
    checkpointer=memory,
    interrupt_before=["tools"]  # Pause before executing tools
)

# Start the run
events = list(app.stream(initial_state, config))
# Graph pauses at "tools" node — waiting for human approval

# Human reviews the pending tool call...
# Resume execution
result = app.invoke(Command(resume="approved"), config=config)

# Method 2: interrupt() inside a node
def review_node(state: AgentState):
    pending_action = state["messages"][-1].tool_calls[0]

    # This PAUSES the graph and surfaces value to the user
    approval = interrupt({
        "action": pending_action,
        "message": "Do you approve this action?"
    })

    if approval == "yes":
        return {"approved": True}
    else:
        return {"approved": False, "messages": [HumanMessage("Action cancelled")]}

🧠 Quiz: LangGraph

6. Why is Annotated[List, operator.add] used for the messages field in LangGraph state?

✅ Correct! The Annotated reducer tells LangGraph how to merge state updates. operator.add appends lists, so each node can return new messages without losing previous ones.
❌ Wrong. Without a reducer, node returns REPLACE state. With operator.add reducer, returns are APPENDED — critical for conversation history.

7. What is the primary purpose of MemorySaver in LangGraph?

✅ Correct! MemorySaver is a checkpointer — it saves graph state snapshots by thread_id. This enables: multi-turn conversations, human-in-the-loop pausing, and workflow resumption after failures.
❌ Wrong. MemorySaver is a checkpointer that persists state snapshots. Use thread_id in config to resume specific conversations.

import semantic_kernel as sk
from semantic_kernel.connectors.ai.open_ai import OpenAIChatCompletion, OpenAITextEmbedding
from semantic_kernel.core_plugins import TextPlugin, TimePlugin
import asyncio

async def main():

    kernel = sk.Kernel()

        service_id="gpt4",
        ai_model_id="gpt-4o",
        api_key="sk-..."

    # 3. Add built-in plugins
    kernel.add_plugin(TextPlugin(), "TextPlugin")
    kernel.add_plugin(TimePlugin(), "TimePlugin")

    summarize = kernel.add_function(
        prompt="Summarize this in 3 bullets: {{$input}}",
        function_name="Summarize",
        plugin_name="SummaryPlugin"

    result = await kernel.invoke(summarize, input="Long article text here...")

asyncio.run(main())

5. Model Context Protocol (MCP)

MCP is an open standard (by Anthropic) that defines how AI assistants connect to external data sources and tools. It's like USB-C for AI — a universal plug that lets any AI client connect to any MCP server. This eliminates the need to custom-build integrations for every tool.

Architecture

ARCHITECTURE
Host (Claude Desktop / AI App)
↔
MCP Client
↔
MCP Server
→
Data Source / API

Host: The AI application (Claude Desktop, VS Code Copilot, your custom app)
MCP Client: Protocol client embedded in the host, speaks MCP
MCP Server: Lightweight server you build that exposes tools/resources
Transport: stdio (local), HTTP+SSE (remote)

Three MCP Primitives

PrimitiveWhat it isExample
ToolsFunctions the AI can call (model-controlled)search_db(), create_ticket(), get_weather()
ResourcesData the AI can read (app-controlled)file://readme.md, db://users/123, git://repo/main
PromptsReusable prompt templates/code-review, /summarize-pr, /explain-error

Building an MCP Server (Python)

from mcp.server import Server
from mcp.server.stdio import stdio_server
from mcp import types
import asyncio

# Create the MCP server
server = Server("my-database-server")

# Declare tools
@server.list_tools()
async def list_tools() -> list[types.Tool]:
    return [
        types.Tool(
            name="search_products",
            description="Search the product catalog",
            inputSchema={
                "type": "object",
                "properties": {
                    "query": {"type": "string", "description": "Search query"},
                    "limit": {"type": "integer", "description": "Max results", "default": 10}
                },
                "required": ["query"]
            }
        ),
        types.Tool(
            name="get_order",
            description="Get order details by order ID",
            inputSchema={
                "type": "object",
                "properties": {"order_id": {"type": "string"}},
                "required": ["order_id"]
            }
        )
    ]

# Handle tool calls
@server.call_tool()
async def call_tool(name: str, arguments: dict) -> list[types.TextContent]:
    if name == "search_products":
        results = await db.search(arguments["query"], limit=arguments.get("limit", 10))
        return [types.TextContent(type="text", text=json.dumps(results))]

    elif name == "get_order":
        order = await db.get_order(arguments["order_id"])
        return [types.TextContent(type="text", text=json.dumps(order))]

    else:
        raise ValueError(f"Unknown tool: {name}")

# Expose resources
@server.list_resources()
async def list_resources() -> list[types.Resource]:
    return [
        types.Resource(
            uri="db://schema",
            name="Database Schema",
            description="Full database schema documentation",
            mimeType="text/plain"
        )
    ]

@server.read_resource()
async def read_resource(uri: str) -> str:
    if uri == "db://schema":
        return open("schema.sql").read()
    raise ValueError(f"Unknown resource: {uri}")

# Run the server
async def main():
    async with stdio_server() as streams:
        await server.run(*streams, server.create_initialization_options())

asyncio.run(main())

from mcp.server.fastmcp import FastMCP

mcp = FastMCP("Analytics Server")

@mcp.tool()
async def run_sql_query(query: str) -> str:
    """Execute a read-only SQL query on the analytics database"""
    results = await db.execute(query)
    return json.dumps(results, default=str)

@mcp.resource("analytics://reports/{report_id}")
