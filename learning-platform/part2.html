🌐 LangGraph — State Machines for AI Pipelines

LangGraph is the most architecturally interesting library in your Code Review Agent. It turns your pipeline from a chain of function calls into a formal state machine that can be composed, branched, and extended without touching existing code.

What Problem Does LangGraph Solve?

Without LangGraph, you have ReviewService.run_review() — a linear function. It works, but:

  • Adding a new step requires editing the existing function (breaks Open/Closed principle)
  • Error handling is scattered with try/except in each step
  • You cannot run steps in parallel (e.g., security scan + LLM review simultaneously)
  • You cannot add conditional branches easily

LangGraph models the pipeline as a directed graph where each node is a pure function. Edges define the flow. The compiled graph is a runnable object you invoke with initial state.

app/agents/review_agent.py — State definition
from __future__ import annotations
import operator
from typing import Annotated, Any, TypedDict
from langgraph.graph import END, StateGraph

class AgentState(TypedDict):
    repo: str
    pr_number: int
    post_comment: bool
    pr_diff: PRDiff | None
    raw_llm_response: str
    parsed_data: dict[str, Any]
    review: CodeReview | None
    review_id: str
    error: str

    # Annotated[list[str], operator.add] is special LangGraph syntax.
    # When a node returns {"logs": ["new entry"]},
    # LangGraph APPENDS to the existing list (reducer = operator.add)
    # instead of REPLACING it. Without this, each node would overwrite
    # the previous logs.
    logs: Annotated[list[str], operator.add]

Nodes — Pure Functions That Return Partial State

Every node receives the full AgentState and returns a partial dict of only the fields it wants to update.

Key pattern: every node first checks if state.get("error") and returns {} immediately. This is the short-circuit pattern — once any node fails, all subsequent nodes silently skip.

async def fetch_diff_node(state: AgentState) -> dict:
    try:
        github = GitHubService()
        pr_diff = github.fetch_pr_diff(state["repo"], state["pr_number"])
        return {"pr_diff": pr_diff, "logs": [f"Fetched diff for PR #{state['pr_number']}"]}
    except Exception as exc:
        return {"error": str(exc), "logs": [f"fetch_diff failed: {exc}"]}

Graph assembly — wiring nodes + edges + compiling
from langgraph.graph import END, StateGraph

def build_review_graph():
    graph = StateGraph(AgentState)

    graph.add_node("fetch_diff",     fetch_diff_node)
    graph.add_node("llm_review",     llm_review_node)
    graph.add_node("parse_response", parse_response_node)
    graph.add_node("build_review",   build_review_node)
    graph.add_node("persist_review", persist_review_node)
    graph.add_node("post_comment",   post_comment_node)

    graph.set_entry_point("fetch_diff")

    graph.add_edge("fetch_diff",     "llm_review")
    graph.add_edge("llm_review",     "parse_response")
    graph.add_edge("parse_response", "build_review")
    graph.add_edge("build_review",   "persist_review")
    graph.add_edge("persist_review", "post_comment")
    graph.add_edge("post_comment",   END)

    return graph.compile()

Mental Model

Think of LangGraph like a factory assembly line. The conveyor belt (graph) moves a work item (state) through stations (nodes). If a station breaks (error), the item is flagged and all downstream stations let it pass without touching it. At any point you can insert a new station or split the line into parallel tracks.

🤖 Anthropic Claude API — Messages, Caching, Streaming

Claude is the LLM powering your Code Review Agent and Lead Classifier. Understanding the SDK deeply lets you optimize cost, avoid timeouts, and explain every API decision.

The Messages API — Core Structure

ParameterTypePurpose

max_tokensintMax tokens in the response

app/services/llm/claude_client.py — with prompt caching
import anthropic
from app.config import get_settings

_SYSTEM_PROMPT = (
    "You are an expert software engineer performing a thorough code review. "
    "You will be given a git diff of a pull request. "
    "Respond ONLY with a single valid JSON object."
    # ... the full JSON schema definition ...
)

class ClaudeClient(BaseLLMClient):
    def __init__(self) -> None:
        settings = get_settings()
        # AsyncAnthropic = async client (use with await)
        self._client = anthropic.AsyncAnthropic(api_key=settings.anthropic_api_key)
        self._model = settings.claude_model

    async def generate_review(self, prompt: str) -> str:
        message = await self._client.messages.create(
            model=self._model,
            max_tokens=4096,
            system=[
                {
                    "type": "text",
                    "text": _SYSTEM_PROMPT,
                    # THIS is prompt caching.
                    # First call: Claude computes + caches this block.
                    # Subsequent calls: reads from cache at ~10% cost.
                    "cache_control": {"type": "ephemeral"}
                }
            ],
            messages=[{"role": "user", "content": prompt}]
        )
        return message.content[0].text

Prompt Caching — How It Saves 90% Cost

Token TypeCost (Sonnet)When charged
input_tokens$3/M tokensNew tokens not in cache (the PR diff)
cache_creation_input_tokens$3.75/M tokensFirst time you cache a block
cache_read_input_tokens$0.30/M tokensSubsequent reads from cache (10% price!)
output_tokens$15/M tokensClaude's JSON response
Minimum size for caching: 1,024 tokens for Claude Sonnet. Your system prompt must be at least that long to be eligible.

📊 PyGithub + HMAC Webhooks

PyGithub is how your Code Review Agent reads PR diffs and posts comments. The webhook endpoint allows GitHub to automatically trigger reviews.

app/services/github_service.py — full walkthrough
import hashlib, hmac
from dataclasses import dataclass
from github import Github, GithubException

@dataclass
class PRDiff:
    repo: str
    pr_number: int
    pr_title: str
    pr_url: str
    author: str
    base_branch: str
    head_branch: str
    files_changed: list[dict]   # [{filename, status, additions, deletions, patch}]
    diff_text: str               # full unified diff as a single string

class GitHubService:
    def __init__(self) -> None:
        settings = get_settings()
        self._gh = Github(settings.github_token)
        self._max_diff_chars = settings.max_diff_chars

    def fetch_pr_diff(self, repo_name: str, pr_number: int) -> PRDiff:
        repo = self._gh.get_repo(repo_name)   # Repository object
        pr = repo.get_pull(pr_number)          # PullRequest object

        files_changed = []
        diff_parts = []

        for f in pr.get_files():  # PaginatedList of File objects
            # f.filename, f.status, f.additions, f.deletions, f.patch
            files_changed.append({
                "filename": f.filename,
                "status": f.status,
                "additions": f.additions,
                "deletions": f.deletions,
                "patch": f.patch or "",
            })
            if f.patch:
                diff_parts.append(f"--- a/{f.filename}\n+++ b/{f.filename}\n{f.patch}")

        diff_text = "\n\n".join(diff_parts)
        if len(diff_text) > self._max_diff_chars:
            diff_text = diff_text[:self._max_diff_chars] + "\n\n[... diff truncated ...]"

        return PRDiff(repo=repo_name, pr_number=pr_number, pr_title=pr.title,
                      pr_url=pr.html_url, author=pr.user.login,
                      base_branch=pr.base.ref, head_branch=pr.head.ref,
                      files_changed=files_changed, diff_text=diff_text)

    def post_review_comment(self, repo_name: str, pr_number: int, body: str) -> str:
        repo = self._gh.get_repo(repo_name)
        pr = repo.get_pull(pr_number)
        comment = pr.create_issue_comment(body)  # posts markdown as PR comment
        return comment.html_url

    @staticmethod
    def verify_webhook_signature(payload: bytes, signature: str) -> bool:
        secret = get_settings().github_webhook_secret
        if not secret:
            return True

        expected = "sha256=" + hmac.new(
            secret.encode(),
            payload,
            hashlib.sha256
        ).hexdigest()

        # compare_digest prevents timing attacks
        # (regular == is vulnerable to timing side-channels)
        return hmac.compare_digest(expected, signature)

HMAC Webhook Security

When GitHub sends a webhook, anyone on the internet could also send a fake POST. HMAC verification proves the request genuinely came from GitHub:

  • You configure a secret in both GitHub webhook settings and your .env
  • GitHub signs every payload with HMAC-SHA256 using that secret, sends signature in X-Hub-Signature-256
  • You recompute the signature on your end and compare
Why hmac.compare_digest()? Regular string comparison short-circuits at the first differing character, leaking timing information. An attacker could brute-force the signature by measuring response times. compare_digest always takes the same time.

Q: Why use hmac.compare_digest(expected, signature) instead of expected == signature?

📄 MongoDB + Motor — Async Database

Motor is the async MongoDB driver. Understanding it means you can explain async database operations and the MongoDB data model.

Why Motor Instead of PyMongo?

PyMongo is synchronous — it blocks the thread while waiting for MongoDB. In a FastAPI async app, blocking the event loop kills performance. Motor provides the same API but all I/O returns awaitables.

OperationPyMongo (sync)Motor (async)
Insertcollection.insert_one(doc)await collection.insert_one(doc)
Find onecollection.find_one(filter)await collection.find_one(filter)
Find manycollection.find(filter).limit(n)await collection.find(filter).limit(n).to_list(n)
Updatecollection.update_one(f, update)await collection.update_one(f, update)
DatabaseService pattern from code_review_agent
from motor.motor_asyncio import AsyncIOMotorClient
from pymongo import DESCENDING
from bson import ObjectId

class DatabaseService:
    def __init__(self):
        settings = get_settings()
        client = AsyncIOMotorClient(settings.mongodb_uri)
        db = client["code_review_db"]
        self._col = db["reviews"]

    async def save_review(self, review: CodeReview) -> str:
        doc = review.model_dump()  # Pydantic model -> plain dict
        result = await self._col.insert_one(doc)
        return str(result.inserted_id)  # ObjectId -> string

    async def get_review(self, review_id: str) -> dict | None:
        return await self._col.find_one({"_id": ObjectId(review_id)})

    async def list_reviews(self, repo: str | None = None,
                           limit: int = 20, skip: int = 0) -> list[dict]:
        filter_q = {}
        if repo:
            filter_q["repo"] = repo
        cursor = (
            self._col
            .find(filter_q)
            .sort("reviewed_at", DESCENDING)
            .skip(skip)
            .limit(limit)
        )
        return await cursor.to_list(limit)

    async def update_review_approval(self, review_id: str,
                                     approved_by: str, posted: bool = True) -> None:
        await self._col.update_one(
            {"_id": ObjectId(review_id)},
            {"$set": {"approved_by": approved_by, "posted_to_github": posted}}
        )

📈 TF-IDF + Cosine Similarity

Used in KeaBuilder AI (Demo 2) and KeaBuilder ML (Demo 1). TF-IDF is a classical NLP technique for finding similar text without any AI model. You must explain the math and know when to use it vs sentence-transformers.

The Math — TF-IDF Explained Simply

TF (Term Frequency): How often does word W appear in document D?

TF(w, d) = count(w in d) / total_words(d)

IDF (Inverse Document Frequency): How unique is word W across ALL documents? Rare words get higher scores; common words like "the" get penalized.

IDF(w) = log(N / df(w))    where N = total docs, df(w) = docs containing w

TF-IDF Score:

TF-IDF(w, d) = TF(w, d) × IDF(w)

Each document becomes a vector where each dimension = TF-IDF score of one word. Cosine similarity measures the angle between two vectors:

cosine_similarity(A, B) = (A · B) / (|A| × |B|)    Range: 0 to 1
demo2_similarity_search/app.py — your exact implementation
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity
import numpy as np

def find_similar(query: str, corpus: list[dict], top_k: int):
    texts = [item["text"] for item in corpus]
    all_texts = texts + [query]  # put query LAST

    vectorizer = TfidfVectorizer(
        ngram_range=(1, 2),   # include unigrams + bigrams ("sales funnel" as one token)
        stop_words="english", # remove: the, is, a, for, ...
        max_features=10000    # keep top 10,000 most informative terms
    )

    # fit_transform: (1) learns vocabulary, (2) transforms all texts to vectors
    # Returns sparse matrix shape: (len(all_texts), vocabulary_size)
    tfidf_matrix = vectorizer.fit_transform(all_texts)

    query_vector = tfidf_matrix[-1]    # last row = query
    corpus_matrix = tfidf_matrix[:-1]  # all rows except last = corpus

    # cosine_similarity returns matrix shape (1, n_docs)
    # [0] unwraps to 1-D array of scores
    scores = cosine_similarity(query_vector, corpus_matrix)[0]

    results = []
    for i, score in enumerate(scores):
        results.append({**corpus[i], "similarity_score": round(float(score), 4)})

    results.sort(key=lambda x: x["similarity_score"], reverse=True)
    return results[:top_k]

Score Interpretation + Limitations

Score RangeMeaning
0.7 – 1.0Strong match — many shared keywords
0.4 – 0.7Partial match — some shared terms
0.1 – 0.4Weak match
0.0 – 0.1No meaningful overlap

Why TF-IDF fails on semantics: "I want to sell my coaching program" and "monetize my mentoring service" share zero keywords, so TF-IDF gives score ~0. This is the limitation that sentence-transformers solves by encoding meaning into dense vectors.
